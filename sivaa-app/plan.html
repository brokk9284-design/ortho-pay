Part 1 — DESIGN.md vs Current CSS: Critical Disconnect

DESIGN.md describes a "Stripi-inspired" system: indigo (#533afd), Sohne/Inter typography, gradient meshes, layered shadows, tabular figures. The actual CSS is "Ollama-inspired": pure black (#000000), Nunito font, no shadows, no gradients, flat monochrome. These are fundamentally different design languages.

Part 4 — Motion & Animation System

The current CSS has motion infrastructure but none of it is applied to actual components. Buttons have basic transition: background-color 120ms but no hover lift, no press spring, no loading state. The site feels static.

Planned Motion Upgrades

  • Button hover lift — translateY(-1px) + Level 1 shadow on hover, spring press on active
  • Card hover — border color shift to indigo + subtle shadow lift + translateX(2px) for transaction rows
  • Page transitions — Route enter: fade + slide-up 8px. Stagger children 40ms apart.
  • Modal/dropdown — Scale-in from 0.95 + fade. Backdrop blur fade-in.
  • Bottom sheet — Spring slide-up from bottom on mobile. Scale-in on desktop.
  • Number count-up — Balance animates from 0 to value on load. Amounts flash green on update.
  • Skeleton loaders — Shimmer on all async content (balance, transactions, KYC, chat).
  • Icon animations — Lucide wrappers: .icon-spin, .icon-pulse, .icon-check-burst, .icon-shake. Coin flip on crypto select, shield animation on KYC verified.
  • OTP digit bounce — Each digit box bounces when filled. Auto-advance with smooth transition.
  • Toggle switch — Spring easing on knob translate. Color fade on track.
  • Tab indicator — Slides smoothly between tabs using transform.
  • Gradient mesh drift — Slow 20s infinite drift on hero gradient. Paused on reduced-motion.
  • Toast slide-in — Spring from right + fade. Exit: fade + slide right.
  • Typing indicator — Three dots bouncing in sequence.
  • Progress bars — Animated width transition with gradient fill.

Data Structure

interface Country {
  code: string;       // ISO 3166-1 alpha-2 (e.g. "US")

  dialCode: string;   // e.g. "+1"
  currency: string;   // ISO 4217 (e.g. "USD")
  regions: string[];  // States/provinces if applicable
  supported: boolean; // Service availability flag

Part 17 — Admin Management Panel (Full Customisation)

A comprehensive admin panel enabling full customisation of fees, limits, user settings, chat oversight, and portfolio management. All settings are configurable per-user, per-group, or globally. The admin panel reads from and writes to the existing database schema (fee_rules, payment_methods, profiles, wallets, transaction_chats, transaction_messages).

17.1 Fee Structure Management

Admin can create, edit, activate/deactivate fee rules and payment method fees. Changes propagate in real-time to user-facing deposit/withdrawal flows. The existing fee_rules table (tier-based) and payment_methods table (per-method fees) are both fully editable.

Tier-Based Fee Rules

  • Edit min/max amount brackets
  • Adjust percentage per tier
  • Activate/deactivate individual rules
  • Add new tiers dynamically
  • Preview fee calculation before saving

Per-Method Fee Configuration

  • Set fee_percentage + fee_fixed per method
  • Configure min/max amounts per method
  • Set daily and monthly limits per method
  • Edit JSONB config (wallet addresses, handles)
  • Toggle method active/inactive
  • Reorder methods via sort_order

17.2 User Management

Admin can view all users, search by paytag/email/phone, filter by KYC status, wallet status, and country. Per-user overrides allow custom fees, limits, and feature access. Bulk actions apply changes to selected users.

Per-User Overrides

  • Custom fee percentage override
  • Custom daily/monthly withdrawal limits
  • Force KYC tier (bypass or require)
  • Freeze/suspend wallet
  • Disable specific payment methods for user
  • Set custom transaction limits

Bulk Actions (Select Users)

  • Apply fee changes to all selected
  • Set uniform limits across selected
  • Freeze/suspend all selected wallets
  • Force KYC re-verification for selected
  • Export selected user data (CSV)
  • Send notification to all selected

17.3 Chat Management & Oversight

Admin can view all transaction chats (transaction_chats + transaction_messages), search by participant, filter by message type (user/system/file), and take moderation actions. Disputes can be resolved by admin directly in the chat context.

Chat Oversight

  • View all 1:1 transaction chats
  • Filter by participant paytag
  • Filter by message type (user/system/file)
  • Search message content
  • View linked payment/escrow context
  • Export chat transcript (PDF/CSV)

Moderation Actions

  • Pin admin message to chat
  • Freeze chat (prevent new messages)
  • Flag chat for dispute review
  • Link chat to support ticket
  • Send system message to both parties

17.4 Portfolio Management Oversight

Admin can view any user's portfolio, wallet balances (wallets), transaction history (wallet_transactions), and escrow holds. Manual adjustments (credit/debit) are logged in the immutable audit_logs table.

Portfolio View

  • View user wallet: total_sent, total_received, locked_balance
  • View all wallet_transactions (ledger entries)
  • View active escrow holds for user
  • View payment history with status breakdown
  • View KYC document submissions

Manual Adjustments

  • Credit user wallet (adjust_in) with reason
  • Debit user wallet (adjust_out) with reason
  • Release escrow hold manually
  • Refund escrow payment manually
  • All actions logged to audit_logs (immutable)
  • Requires super_admin for adjustments > $1,000

Part 18 — Icon System (Animated / Flat, No Emojis)

All emojis are removed from the project. Icons are rendered as SVG-based components with two states: flat (static, default) and animated (on hover, focus, or interaction). This ensures consistent rendering across platforms, better accessibility, and a professional fintech aesthetic.

Icon States

Flat (Default)Static SVG, 1.5px stroke, currentColor
Animated (Hover)SVG with CSS transition: scale 1.1, rotate 5deg, color shift
Animated (Active)SVG with keyframe: pulse, spin, or bounce depending on context
Animated (Loading)SVG with spin animation (e.g. processing state)
Animated (Success)SVG with checkmark draw animation (stroke-dashoffset)

Part 19 — Paytag Naming Convention

The user identifier system uses "paytag" with a $ prefix symbol. This replaces the previous "siva_tag" / "$ORTHO" naming. The database column siva_tag in the profiles table should be renamed to paytag in a migration. Display format: $username (e.g. $alex_m).

TermValueExample

DB column (target)paytagprofiles.paytag
Validation^[a-zA-Z0-9_]{3,30}$3-30 chars, alphanumeric + underscore
